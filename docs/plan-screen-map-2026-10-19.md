## 1. 왜 하나

화면마다 그 자리에서 필요한 걸 덧붙이다 보니 같은 질문을 여러 화면이 따로 답하고, 답도 서로 다르다.
사용자가 "모아가기 4번에서 10억 계산 → 종목은? → 섞으면? → 계좌는?"을 따라가다 막힌 지점이 모두 여기서 나왔다.

| 질문 | 지금 답하는 화면 | 문제 |
|---|---|---|
| 목표까지 매달 얼마 / 언제 닿나 | 모아가기 4번, 계획 점검 "목표 금액까지 매달 얼마가 필요한가", 목표 트래커 "필요 시드에 닿으려면 매달 얼마" | **세 곳, 계산 기준이 셋 다 다르다**: 목표 트래커는 고정 연 8%(`DEFAULT_PLAN_ANNUAL_PCT`), 모아가기 4번은 코스피200 과거 이력(15년 적립 환산 약 5.7%·명목), 계획 점검은 오늘 물가로 환산한 실질 범위. 같은 목표에 화면마다 다른 금액이 나온다 |
| 어떤 지수로, 어떤 비중으로 | 모아가기 1번(코스피200 상품 하나), 계획 점검 "코스피냐 미국이냐", 섞어보기 "비중 정하기" | 저장되는 건 상품 **하나**뿐. 섞어보기에서 정한 비중은 어디에도 이어지지 않는다 |
| 어느 계좌에 무엇을 | 리밸런싱 가이드(계좌별 목표 비중), 계획 점검 "이 계좌는 언제 쓸 돈인가요", 포트폴리오 '이 계좌의 방향' | 계좌 배치(해외지수는 ISA·연금, 코스피는 일반)를 안내하는 곳이 없다 |
| 이번 달 무엇을 몇 주 | 홈 '[실제] 이번 달 할 일' | 상품 하나만 안내 |

**뿌리는 모아가기 1번이다.** "같은 코스피200 지수를 따라가는 상품 중 하나 고르기"로 설계돼 있어(`INDEX_ETF_CANDIDATES`에 코스피200 일반·TR만), 뒤의 시뮬레이션·목표 계산·홈 할 일·가상 계좌가 전부 "상품 하나"를 전제로 이어진다.

## 2. 원칙

1. **질문 하나에 집 하나.** 같은 질문을 두 화면이 답하지 않는다. 다른 화면은 그 집으로 가는 링크만 둔다.
2. **저장되는 "내 계획"은 하나.** 매달 금액·넣는 날·버틸 하락폭·개별주 몫에 **구성(지수·비중·지수별 상품·계좌)**을 더한다. 바꾸는 곳은 모아가기 '내 계획'과 1번(구성) — 다른 화면은 읽기만 하거나 "이 값으로 정하기" 버튼으로 같은 저장 경로를 쓴다.
3. **할 일은 언제나 실제 계좌에만.** 가상 계좌는 계획대로 자동. [실제]/[가상] 글자 표시 유지.
4. **순위·"최선의 조합"을 제시하지 않는다.** 과거에 좋았던 조합을 고르게 되기 쉽다(나스닥100은 가장 좋았던 14년뿐). 비교는 이력 기간·최대 낙폭과 함께, 이력 긴 순서로.
5. **계좌 배치는 안내까지.** "해외지수 → ISA·연금, 코스피 → 일반"은 세법상 일반론이고, 효과 크기는 가설 H18(자산 위치)로 아직 측정 전이라 규칙으로 강제하지 않는다.
6. **계산 기준은 하나로, 화면에 적는다.** 목표 계산이 화면마다 다른 기준을 쓰지 않는다(결정 필요 1).
7. **가상 계좌의 매매 방식 변경은 11/23 관문 뒤.** 여러 종목을 비중대로 사는 것은 자동매매 규칙 변경이다.

## 3. "내 계획" 구성 (데이터 초안)

`users.prefs` 의 투자 계획(`src/services/userPlan.ts` `InvestPlan`)에 선택 필드를 더한다. 없으면 지금처럼 코스피200 100%로 읽는다(하위 호환).

```ts
mix?: Array<{
  index: 'kospi200' | 'sp500' | 'nasdaq100'   // 처음엔 이 셋만 (섞어보기의 채권·금은 실험용으로 남김)
  weight: number                              // 0~1, 합 1
  product: { code: string; name: string } | null  // null이면 지수별 추천 규칙(규모·거래대금·보수)
  account: { broker: string; account: string } | null  // null이면 안내만, 사용자가 고르기 전
}>
```

- 저장 경로는 지금과 같은 `/api/ui/investment-prefs` 부분 수정(`mergeInvestPlan`). CHECK·검증은 서버에서(합 1, 지수 목록, 중복 금지).
- 모아가기 1번의 직접 지정(`accumulate.target`, user-state)은 구성으로 옮긴 뒤 읽기만 남기고 정리한다.

## 4. 화면 지도

| 화면 | 이 화면의 질문 | 남길 것 | 옮길 것 | 지울 것 |
|---|---|---|---|---|
| **홈** | 오늘 내가 할 일 | '[실제] 이번 달 할 일'(구성대로 **여러 줄**: "ISA에서 S&P500 ○주, 일반에서 코스피200 ○주"), 해마다 늘리기 1월 알림, 내 모으기 요약 | — | — |
| **모아가기** | 무엇으로, 얼마씩 모으면 어떻게 되나 (계산기·기록장) | **1번 재구성**(아래 5절) · 2번 계산기 · 3번 과거 시뮬레이션(구성 이력으로) · 5번 지금 상황 · 내 기록 · 목돈 나눠 넣기 · '내 계획' 카드 | 4번 '목표에서 거꾸로' → 목표 트래커 | 1번의 "코스피200 상품 하나" 전제 |
| **목표 트래커** | 얼마를, 언제 닿나 | 은퇴 나이·목표·계획대로 가고 있나·복리가 입금을 넘는 시점 | 받음: 모아가기 4번(기간 고르기·"내 계획이면 n년 뒤 얼마"·언제 닿나·더 빨리 닿는 선택지), 계획 점검 목표 계산 | 겹치는 "필요 시드에 닿으려면 매달 얼마" 표는 받은 4번과 하나로 |
| **섞어보기** | 어떤 비중이면 어땠나 (실험) | 비중 정하기·결과·하락 가정·읽을 때 주의 | — | — · 추가: **[이 비중으로 정하기]**(코스피200·S&P500·나스닥100 비중만 내 계획 구성으로 저장, 채권·금이 섞이면 버튼 대신 안내) |
| **계획 점검** | 내 마음가짐 (버틸 낙폭, 얼마나 자주 볼까, 한 번에 vs 나눠, 금리 환경) | 그 항목들 | "목표 금액까지 매달 얼마" → 목표 트래커 링크, "코스피냐 미국이냐" → 모아가기 1번 ①의 근거(펼침) + 섞어보기 링크 | 중복 계산 |
| **리밸런싱 가이드** | 계좌별로 지금 무엇이 목표보다 많고 적나 | 할 일 3개·예수금·같은 지수 상품 선택 | 계좌별 목표 비중이 **내 계획 구성·계좌 배치를 읽게** | 구성과 따로 노는 목표 비중 입력(있다면) |
| **따라 사기** | 계획을 지켰나 | 달별 '계획 vs 실제' 표·결산 | 구성별 줄(지수마다 지킴/건너뜀) | — |
| **포트폴리오** | 지금 가진 것 | 그대로 ([실제]/[가상] 탭) | — | — |

"이 계좌는 언제 쓸 돈인가요"(계획 점검)는 계좌 성격이라 리밸런싱 가이드 계좌 설정이나 포트폴리오 '이 계좌의 방향'으로 옮길 후보 — 결정 필요 4.

## 5. 출발점: 모아가기 1번 재구성 (스케치)

```
1. 무엇으로 모을까
 ① 구성 (지수 단위)
   [코스피200만] [코스피·S&P 반반] [셋 같은 비중] [직접 정하기 → 섞어보기]
   구성마다 한 줄: 이력 시작 연도 · 과거 적립 연평균(보통~운 나쁨) · 최대 낙폭   ← 순위 아님, 이력 긴 순서
   펼침: 코스피냐 미국이냐(계획 점검에서 옮김) · 이력이 짧고 좋았던 구간일수록 좋게 나온다는 주의
 ② 지수마다 상품 (지금 추천 규칙을 지수별로 그대로: 규모·거래대금·상장기간 관문 → 최저 보수 묶음 → 순자산 큰 쪽)
   코스피200 → KIWOOM 200TR   보수 · 순자산 · 거래대금
   S&P500   → (후보 중 추천)   ...
   나스닥100 → (후보 중 추천)   ...
   [직접 지정] 은 지수별로
 ③ 어느 계좌에 (안내 + 사용자가 고름, 저장은 구성의 account)
   해외지수 → ISA·연금저축·IRP가 세금에 유리할 수 있음(일반 계좌는 매매차익·분배금 15.4%)
   코스피200 → 일반 계좌도 매매차익 비과세
```

- 1번이 바뀌면 2·3번은 구성 이력(섞어보기의 월별 재조정 계산 재사용 — 웹 `lib/mix.ts`와 일치 확인)으로, 홈 할 일은 구성대로 여러 줄로 바뀐다.
- 일반형·TR형 선택(키우기/분배금 받기)은 지수별 상품 고르기 안에 남긴다.

## 7. 결정 필요

1. **목표 계산 기준 하나로**: (a) 고른 구성의 과거 이력(지금 모아가기 4번 방식, 15년 넘는 길은 연평균으로 늘린 추정) (b) 사용자가 정하는 고정 연 수익률(지금 목표 트래커 8%) (c) 둘 다 보여 주되 기본은 (a). — 제안: (c), 기본 (a), 고정률은 "내가 가정한 수익률" 칸으로.
2. **구성 프리셋**: 코스피200만 / 코스피·S&P 반반 / 셋 같은 비중 + 직접. 나스닥100 단독을 프리셋에 넣을지(집중도·짧은 이력 때문에 제안은 "넣지 않음, 직접 정하기로만").
3. **명목 vs 실질**: 계획 점검은 오늘 물가 기준, 나머지는 명목. 통합 시 한쪽으로(제안: 명목 + "오늘 물가로 보면" 한 줄).
4. "이 계좌는 언제 쓸 돈인가요"의 새 자리.
5. 가상 계좌 구성 반영 시점(제안: 11/23 판정 뒤, 그 전엔 가상 계좌는 지금처럼 코스피200 — 화면에 "가상 계좌는 아직 코스피200만" 표시).

## 8. 하지 않는 것

- "최선의 조합" 순위·추천, 과거 수익률로 비중 자동 최적화
- 레버리지·인버스·커버드콜을 구성 후보로 넣기
- 증권사 API 연동(실계좌는 사용자가 알려 준다)
- 개별주를 구성에 넣기(개별주 몫은 기존 '개별주 몫' 설정 그대로)
