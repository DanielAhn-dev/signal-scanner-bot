# 시뮬레이터 개편 계획 (2026-10-22)

> 상태: 2026-10-22 추천안 승인(8절). **1단계 엔진·2단계 데이터 완료**(`web/src/lib/sim/engine.ts`, `web/src/data/simData.ts`). 다음은 3단계 화면.
> 배경: 시뮬레이터·백테스터는 "개별주 발굴·스윙·단타"를 시험하던 시절의 도구다. 지금 제품 방향(정기 지수 적립·목표·행동 실수 차단, 2026-09-29 전환)과 맞지 않는다. 사용자가 원하는 것은 **연도·자산 구성·넣는 방식(일시금·월 적립)을 자유롭게 골라 "그랬다면 지금 얼마"를 보는 도구**다.

## 1. 지금 무엇이 있나 (현황 진단)

| 화면 | 하는 일 | 자유도 | 방향과의 관계 |
|---|---|---|---|
| **시뮬레이터** `features/simulator` | 개별 종목·승률·손익비·켈리로 금액 나누기, 잘 풀릴 때/안 풀릴 때 손익 | 종목만 자유, 기간·과거 가격 없음 | **옛 방향**(개별주 단기). 메뉴 "계산·주문 정리" |
| **백테스트** `features/backtest` | 급등 종목 역추적 → 상승 전 공통 패턴 | 종목 연구용 | **옛 방향**. "후보 더 보기"(종목 연구) |
| **섞어보기** `features/mix` + `lib/mix.ts` | 6자산 비중 → 연수익·MDD·최악 1년·5년 롤링, 하락 가정 | 비중은 자유 | 방향 맞음. 단 **금액이 없음**(시작=1배 곡선), **기간 선택 없음**(가장 짧은 자산 이력 전체), 비교 대상 코스피200 고정, 구성 1개만 |
| **모아가기 3번 기간 보기** `accumulate/PeriodSim` + `simulatePeriod` | 시작월·기간·월 적립·일시금 → 원금 대비 % | 기간·금액 자유 | 방향 맞음. 단 **내 계획 구성(3지수)에 묶임**, 채권·금 불가, 다른 구성과 비교 불가 |
| **모아가기 앞으로 10년** `FutureView` + `futurePaths` | 과거 12개월 블록 부트스트랩 경우의 수 | 3지수만 | 미래 범위용. 유지 |
| **목표 트래커** `goalReach` | 고정 연수익률 가정으로 n년 뒤·도달 시점 | 수익률 가정 | 과거 가격 아님. 유지 |

**핵심 문제**

1. **계산 엔진이 5개로 흩어져 있다** — `simulateMix`(비중·리밸런싱, 금액 없음), `simulatePeriod`(적립·일시금, 단일 시계열), `simulateDca`, `simulateFuture`, `projectValue`. 화면마다 고를 수 있는 것이 다르고, "구성 + 기간 + 금액"을 한 번에 넣는 곳이 없다.
2. **결과가 '배수'로만 나온다**(섞어보기). 사용자는 "월 50만원씩 2015년부터 넣었으면 지금 얼마"를 원한다.
3. **비교가 안 된다.** 내 구성 vs 코스피200만 vs 반반 같은 비교를 나란히 못 본다.
4. **"운"이 안 보인다.** 고른 한 기간 결과만 보면 체리피킹이 된다. 같은 길이를 **모든 시작 시점**으로 돌렸을 때의 범위가 같이 나와야 한다(`simulatePeriod`의 `worsePct`가 단일 시계열로만 이걸 한다).
5. 옛 시뮬레이터가 "시뮬레이터"라는 이름을 차지하고 있어, 사용자가 기대하는 기능과 이름이 어긋난다.

## 2. 목표 모습

**"새 시뮬레이터" 한 화면 = 과거 실제 가격으로 내 돈 넣어 보기.** 질문 하나: *"이 구성에 이렇게 넣었다면 어땠을까?"*

### 입력 (모두 자유)

| 항목 | 선택지 |
|---|---|
| 기간 | 시작 연·월 ~ 끝 연·월 / 빠른 선택(최근 5·10·15·20년, 2008 금융위기 직전, 2020 코로나 직전, 고점 직후) |
| 구성 | 프리셋(현재 섞어보기·모아가기 프리셋 통합) 또는 자산별 비중 직접. **최대 3개 구성 나란히 비교** (A=내 계획 구성 자동 채움, B=코스피200만 기본) |
| 넣는 방식 | 일시금 / 월 적립 / 둘 다 + **해마다 적립액 n% 늘리기**(목표 트래커와 같은 개념) |
| 리밸런싱 | 매월 / 1년에 한 번 / 안 함 / (선택) 새 돈으로만 맞추기 |
| 비용·세금 | 총보수 차감(기본 켬), 리밸런싱 비용 0.1%, 계좌 종류 단순 옵션(일반·ISA·연금 — 세금 대략, **기본 끔**, "대략"임을 표시) |

### 출력

1. **금액 그래프**: 넣은 돈(계단) vs 평가금(구성별 선). 세로축 금액/원금 대비 % 전환.
2. **요약 타일**(구성별 열): 끝 금액, 넣은 돈, 손익, 내 돈 기준 연수익률(적립이 있으면 금전가중 IRR), 최대 낙폭(평가금 기준), **원금 아래였던 가장 긴 기간**, 회복까지 걸린 달.
3. **같은 길이, 다른 시작 시점** — 데이터 안의 모든 시작월로 같은 기간·같은 금액을 돌린 결과 분포(최저·하위 10%·중앙·최고) + "내가 고른 기간은 이 중 몇 번째". 체리피킹 방지 장치이자 "운의 범위" 표시.
4. **하락 가정**(섞어보기에서 이동): 지금 구성에 충격을 줬을 때 금액 손실·버틸 선 비교.
5. **읽을 때 주의 / 출처**: 가장 짧은 자산이 기간을 정함, 원화 환산·보정, 분배금 반영 수정주가, 세금 미반영, 데이터 기준월·생성일(180일 지나면 낡음 표시).

### 하지 않는 것 (방침)

- "최고의 조합" 순위·자동 최적화 버튼 없음(과거 최적은 나스닥100 1등이 되는 사후 선택).
- 레버리지·인버스 자산 없음.
- "기대 수익" 같은 보장성 문구 없음. 과거 숫자라는 표시를 결과 바로 위에.
- 새 매매 규칙이 아니라 계산 도구라 11/23 관문과 무관(규칙·가이드에 자동 반영하지 않음).

## 4. 메뉴·흐름 정리

| 지금 | 바뀐 뒤 |
|---|---|
| 목표·계획 › **섞어보기** | → **시뮬레이터**로 흡수. `/mix`는 시뮬레이터로 이동(redirect). 하락 가정·`DropPlanCard`·`BehaviorGap`은 시뮬레이터 아래 접힌 섹션 |
| 계산·주문 정리 › **시뮬레이터**(개별주) | → 이름을 **"종목 금액 나누기(실험)"**로 바꾸고 관리자 전용 실험 메뉴로. 가상 계좌 개별주 실험용으로만 남김(가상=개별주 실험·하락 대응 학습 방침과 일치). 시드 만들기·실행가이드 연결은 그대로 |
| 종목 연구 › **백테스트** | → 이름을 **"급등 역추적(연구)"**로만 바꿈. 기능 변경 없음(관리자 연구용). 지수 백테스트는 새 시뮬레이터가 맡는다 |
| 모아가기 3번 "기간 골라 보기" | 요약 1줄 + **[시뮬레이터에서 직접 바꿔 보기]**(지금 구성·금액을 채워 이동). 전체 조작은 시뮬레이터 한곳 |
| 목표 트래커 | 가정 수익률 투영은 유지 + **[과거 실제로 돌려 보기]** 링크(목표 금액·월 적립·기간을 채워 이동) |
| 계획 점검 "코스피냐 미국이냐" | 섞어보기 링크 → 시뮬레이터 링크 |

이동 시 값 전달은 URL 쿼리가 아니라 세션 저장소(금액은 개인 정보에 가까움).

## 5. 계산 엔진 통합

`web/src/lib/sim/engine.ts` (순수 함수 하나):

```ts
simulatePlan({
  weights, startYm, endYm,
  lump, monthly, monthlyRaisePct,
  rebalance: 'month' | 'year' | 'none' | 'cashflow',
  feeDrag: true, rebalanceCost: 0.001, tax?: 'none' | 'rough-general' | ...
}) → { yms, paid[], value[], stats: { endValue, paidTotal, irr, mdd, longestUnderwaterMonths, recoveryMonths } }

rollingStarts(sameInputs, lengthMonths) → { count, min, p10, median, max, rankOfChosen }
```

- **같은 시점 규칙 유지**: 월초 매수·월말 평가(`simulatePeriod`와 동일 — "i개월 뒤 평가금 = i번 넣은 단위 × 그 달 가격"). 리밸런싱 비용·`dragPct`는 `simulateMix`와 동일.
- **불변 테스트 먼저**: (a) 적립 0·일시금 1 → `simulateMix`의 `curve`와 같음, (b) 코스피200 100% → `simulatePeriod`와 같음, (c) 리밸런싱 none·단일 자산은 리밸런싱 비용 0. 이게 통과한 뒤 기존 함수들을 새 엔진 위로 옮긴다(호출부 동작 그대로).
- 서버 사본 확인: `src/data/planIndexMonthly.ts`(같은 스크립트가 생성)를 쓰는 서버 계산이 있으면 `diff`로 규칙 동일성 확인.
- 롤링 분포는 시작 시점 수 × 개월(≈300×300) 계산 — 구성 3개여도 수 ms 수준이지만, 실측 후 필요하면 `useDeferredValue`.

## 6. 데이터 확장 (`build_mix_data.py` → 자산 메타 추가)

지금 6개: 코스피200(2002-10~), 나스닥100(2010-10~), S&P500(SPY 원화, 2003-12~), 국고채10년(2011-10~), 미국장기채(TLT 원화, 2002-07~ / 환율 때문에 2003-12~), 금(2010-10~).

추가 후보(`.research-cache/allweather`에 이미 있음, 새 수집 불필요):

| 자산 | 원천 | 시작 | 주의 |
|---|---|---|---|
| 현금(CD91) | cd91.json | 1998~ | 금리→월 수익 환산 |
| 미국 중기채 | IEF 원화 | 2003-12~ | 환노출 |
| 선진국 주식 | EFA 원화 | 2003-12~ | |
| 신흥국 주식 | EEM 원화 | 2003-12~ | |
| 미국 리츠 | VNQ 원화 | 2004-10~ | |
| 코스닥 | KQ11 지수 | 1996~ | **가격만(분배금 없음)** — 표시 필요 |

- 원화 환산 환율이 `KRW=X`로 2003-12부터라 미국 자산은 그 전으로 못 간다. `futurePaths`가 쓰는 ECOS 환율(1999-04~)로 바꾸면 SPY·TLT를 1999년까지 늘릴 수 있다(재료 있음).
- 1970년대까지(Shiller S&P500 총수익)는 별도 단계 — 한국 자산과 기간이 안 겹쳐 "미국만 장기" 보기로만 의미가 있다.
- 자산마다 `class`(주식/채권/금/현금/리츠), `priceOnly`, `fxConverted`, `note`를 메타로 넣어 화면 주의 문구를 자동 생성.
- 용량: 지금 mixData 32KB. 12자산 ≈ 70KB → 시뮬레이터 화면에서만 동적 import(항상 마운트되는 곳에서 import 금지).

## 9. 진행 기록

- **1단계(2026-10-22)**: `simulatePlan`·`rollingStarts`·`commonMonths`·`annualIrr`.
  - 불변 확인: 섞어보기 프리셋 7개 × 리밸런싱 3종에서 일시금 1·적립 0이면 `simulateMix.curve`·연수익·MDD와 같음. 코스피200 단독 3개 기간에서 `simulatePeriod`의 paid·value·최저점·회복·시작점 수·worsePct와 같음.
  - drag 적용 방식만 다름(`simulatePeriod` 곱셈 vs `simulateMix` 뺄셈) — S&P500 10년에서 끝 금액 차이 0.2% 미만. 엔진은 섞어보기 방식.
  - 시간가중 지수(`index`)는 "1을 한 번에 넣은 경로"라 넣는 돈과 무관 → MDD·연수익은 구성 자체, `irr`은 내 돈 기준.
  - 성능: 시작월 분포가 처음 구성당 ~200ms → 가격 배열 선계산·분포에서 IRR 생략으로 ~10ms(vitest 실측).
  - 기존 함수(`simulateMix`·`simulatePeriod`)는 아직 그대로. 엔진으로 옮기는 것은 3~5단계에서 호출부를 바꿀 때 한다.

- **2단계(2026-10-22)**: `scripts/research/build_sim_data.py` → `web/src/data/simData.ts`(13자산, 86KB — 시뮬레이터 화면에서만 동적 import할 것).
