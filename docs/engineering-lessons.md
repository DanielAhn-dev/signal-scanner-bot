# 엔지니어링 교훈 — 이전 프로젝트에서 실제로 겪고 고친 것들

이 문서는 다른 프로젝트(React + TS + Vite + Tailwind + Zustand + Supabase + Vercel + pnpm 모노레포)에서 실제 사고·재작업으로 확인된 규칙이다. 해당 스택이 아니면 원칙만 적용한다. 각 항목은 "하지 말 것 → 대신 할 것" 순서다.

## 0. 작업 습관 (가장 자주 재발한 것)

- **타입체크 "통과" 보고 전에 실제 실행한 커맨드를 확인한다.** solution-style tsconfig(`files: []` + `references`)에서는 `tsc --noEmit`, `tsc -p .`, 그리고 이를 감싼 `type-check` 스크립트도 아무것도 검사하지 않고 exit 0을 낸다. 5번 재발했다. `tsc -p tsconfig.app.json --noEmit`을 쓰고, 커밋 전에는 배포와 같은 `pnpm --filter <app> build`를 반드시 한 번 돌린다. 내가 안 건드린 파일에서 에러가 나면 무시하지 말고 원인을 찾는다.
- **SQL·마이그레이션은 tsc가 잡지 못한다.** 함수·컬럼을 참조하는 새 SQL은 그 이름으로 가장 최근 마이그레이션 파일을 찾아 최신 시그니처와 대조한다(서브에이전트가 작성한 SQL은 특히).
- **같은 이름의 파일·로직이 두 앱에 있으면 동일하다고 가정하지 않는다.** `diff`로 먼저 확인한다. 손으로 포팅한 사본은 반드시 한쪽만 고쳐진다(클라이언트/서버 요율 리졸버, 관리자/게스트 UI 모두 실제로 갈라졌다). 두 번째 앱에 붙는 순간 공용 패키지로 추출한다(타입 + 로직 + 쓰기 래퍼는 패키지, 뷰만 앱별).
- **"코드는 맞는데 화면에 안 보인다"** → 브라우저 캐시보다 먼저 최근 배포 로그에서 빌드 실패 여부를 확인한다.
- **진단 전에 실측한다.** 번들 크기, 느린 쿼리, 렌더 비용 모두 추측으로 범인을 지목했다가 틀렸다. 측정 결과로 대상을 고른다.
- **엄격한 조건 때문에 결과가 비어 보여도 바로 완화하지 않는다.** 코드 버그인지, 운영에서 그 단계(마감·승인·final)를 아직 안 쓰고 있는 것인지 먼저 확인한다.
- **정책 예외가 있을 수 있는 값**(합계 100% 등)은 하드 차단 대신, 값을 보여주고 의도를 묻는 확인창으로 처리한다. 하드 차단은 "항상 틀린 값"(음수, 필수 누락)에만 쓴다.
- **구조나 흐름을 바꾸는 UI 변경은 코드 전에 스케치로 승인받는다.** 라벨 교체 같은 1:1 수정은 바로 해도 된다.
- **국소 튜닝보다 구조적 지점을 먼저 본다.** 공용 레이아웃·TopBar·Button 한 곳을 고치면 수십 개 화면에 한 번에 반영된다.

## 1. Git·배포

- 커밋은 기능·단계·성격 전환마다 잘게 나눈다. "커밋"이라는 말만 들었어도 diff를 성격별로 나눠 여러 논리 커밋으로 만들고, 의존 순서(공용 패키지 → 앱)를 지켜 각 커밋이 빌드 가능하게 한다.
- `git add -A`는 금지. 파일을 지정한다. 커밋 직후(amend 포함) `git show --stat HEAD`로 의도한 파일만 들어갔는지 확인한다. 여러 세션이 같은 디렉토리를 쓰면 amend가 남의 스테이징을 끌어오고, 반대로 남의 `add -A`가 내 변경을 가져간다. 동시 작업이 의심되면 worktree에서 작업한다.
- 다른 세션이 같은 파일을 편집 중이면 Edit할 때마다 다시 Read한다.
- **push는 모아서 한다.** 모노레포가 커밋 하나에 여러 Vercel 프로젝트로 fan-out되면 Hobby 일일 100회 한도를 금방 소진한다(실제로 24시간 배포 불가 사고가 났다). 로컬 빌드 검증과 push는 별개 판단이다. 연속 push는 진행 중인 배포를 Canceled로 만들고, 취소된 배포는 자동 재시도되지 않는다.
- Ignored Build Step의 `exit 0`은 수동 Redeploy까지 막고, 취소된 빌드도 한도에 카운트된다. 경로 기반 스킵 스크립트는 "확실하지 않으면 빌드"(PREV_SHA 없음·diff 실패 시 exit 1)로 만든다.
- **Vercel + pnpm 캐시 손상**: 로컬은 정상인데 Vercel에서만 특정 패키지(peer-hash 접미사가 붙은 네이티브/wasm 패키지)를 resolve하지 못하고, 실패 양상이 매번 다르면 캐시 손상이다. `installCommand`에 `--force`를 넣는다. 끄면 바로 재발해서 결국 상시 유지했다.
- Windows에서 dev 프로세스가 네이티브 바이너리를 잠근 상태로 `pnpm install`을 하면 패키지가 `package.json` 없이 깨진다(`Cannot find module @rollup/...`, 옆에 `_tmp_` 디렉토리). 프로세스 종료 → 해당 `.pnpm` 디렉토리 삭제 → `pnpm install --force` → 실제 dev 서버 기동까지 확인한다.
- **서버리스 API(plain node)는 raw `.ts` 워크스페이스 패키지를 import할 수 없다.** 로컬 tsx에서는 통과하지만 배포에서는 모든 라우트가 `FUNCTION_INVOCATION_FAILED`가 된다. 패키지가 `dist/*.js`를 노출하는지 확인하고, `node`로 `import('./src/index.js')`를 실행해 검증한다.
- **로컬 dev와 운영이 같은 DB를 쓰면** `setInterval` 예약 작업(리마인더·다이제스트)을 `RUN_BACKGROUND_JOBS`(VERCEL_ENV === 'production' 우선) 같은 가드로 감싼다. 감싸지 않으면 알림이 중복 발송된다.
- 상시 캐시 워머는 사용자가 없는 밤·주말에도 egress를 만든다(하루 3~5GB). 최근 실사용이 있을 때만 워밍하는 유휴 게이트를 두고, 쓰기 시점 무효화로 신선도를 보장하면 TTL을 길게 잡을 수 있다.
- 마이그레이션을 운영 SQL 에디터에 직접 붙여넣지 않는다. 스테이징 프로젝트 → on-demand 백업 → `supabase db push` 순서로 하고, 데이터 손실 위험이 있는 변경에는 롤백 스크립트를 같이 둔다.
- worktree를 앱 디렉토리 아래 두지 않는다. vitest 등의 설정 상향 탐색이 바깥의 진짜 config를 집어 엉뚱하게 실패한다.

## 2. Supabase / PostgREST / Postgres

### 조회 규모
- **응답은 1000행에서 조용히 잘린다**(`db.max_rows`). `.limit(20000)`을 써도 1000건이 온다. 1000건을 넘을 수 있는 조회는 처음부터 `.range()` 루프로 페이지네이션한다. 결과가 정확히 1000의 배수면 이 캡을 의심한다. 한 번 전수 감사한 뒤에도 새 스크립트에서 다시 재발했다.
- "최신 1건만 남기고 삭제"를 전체 id 조회로 구현하면 1000건을 넘는 순간 오래된 행이 영영 정리되지 않는다. 최신 id 하나만 가져와서 `neq`로 삭제한다.
- **`.in()` 배열은 호출부 규모에 비례하는지 확인한다.** 1,900개 키를 `.in()`으로 보낸 요청 하나가 커넥션 풀을 붙잡아서 무관한 페이지까지 타임아웃시켰다. 대상 테이블이 작으면 필터 없이 전부 가져와 JS에서 매칭한다. 한글 키는 퍼센트 인코딩으로 100개만 넣어도 URL이 10KB가 되어 `fetch failed`가 난다. 부모 키로 조회하고 JS에서 인덱싱한다.
- `.or()` 안의 `neq`/`<>`는 인덱스를 타지 못한다. 닫힌 enum이면 나머지 값의 `in`으로 바꾸거나 쿼리를 둘로 나눠 병합한다. `.or()` 안에 `in.(...)`처럼 괄호를 여는 연산자를 중첩하면 500이 난다.
- statement_timeout은 role별로 따로 확인한다(`SELECT rolname, rolconfig FROM pg_roles`). DB 기본값은 2분이었지만 `authenticated`만 8초였다. 실패 시간이 들쭉날쭉하면 동시 요청에 따른 커넥션 대기를 의심한다.
- 로그인·새로고침 때 전역에서 스토어 10여 개를 `Promise.all`로 한꺼번에 로딩하지 않는다. 헤더·알림벨·홈처럼 정말 모든 페이지에 필요한 것만 전역에 두고, 나머지는 해당 페이지 마운트 시 로딩한다.
- "boolean 플래그를 미리 계산해 두고 백필"하는 방식은 백필이 끝날 때까지 에러 기간이 생긴다. 검증된 기존 인덱스를 올바른 연산자로 조합하는 쪽이 거의 항상 낫다.
- **저사양 DB에서는 진단용 단건 조회조차 서버를 다운시켰다.** 운영 DB 조회·스크립트 실행 전에는 사용자에게 확인받는다. 522나 schema cache 에러가 나면 즉시 모든 DB 접근을 중단한다.
- 대형 테이블 백필은 끝까지 쉬지 않고 돌리지 않는다(2.5시간 drain으로 프로젝트가 unhealthy가 됐다). 1만 건 단위로 끊고 pause를 두며, 재개 가능하도록(`where 처리컬럼 is null`) 만든다.
- 이름 매칭에서 지역 같은 타이브레이커는 후보가 1개뿐이어도 반드시 대조한다. "후보 1개면 채택"으로 했더니 16%가 오매칭됐다.

### RLS / 권한
- 관리자 콘텐츠 테이블의 쓰기 정책을 `using(true)`로 두지 않는다. 프론트엔드 권한 체크는 UI만 막는다. `user_can_manage_app(app_id, email)` 같은 SECURITY DEFINER 헬퍼를 정책에 넣는다.
- **RLS 정책에서 다른 RLS 테이블을 인라인 EXISTS로 참조하지 않는다.** A↔B 양방향 참조는 무한 재귀로 이어져 모든 조회가 500이 된다. SECURITY DEFINER stable 함수로 감싼다.
- 행마다 SECURITY DEFINER 마스킹 함수를 호출하면 느리다(18,584행에 30초). 호출자 기준으로 고정되는 조건은 인라인 서브쿼리로 풀어 InitPlan으로 한 번만 평가되게 한다(1.4초로 단축).
- **`.insert().select()`는 RETURNING 때문에 SELECT 정책까지 통과해야 한다.** "수신자 본인만 조회" 테이블에 남에게 보내는 행을 넣으면 42501이 난다. `upsert`는 수정이어도 INSERT의 WITH CHECK를 검사한다. 남의 행은 select 없이 insert하고, 수정은 `update().eq().select('id')`로 0행인지 확인한다.
- RLS를 좁히기 전 사용처를 grep할 때는 `apps/`뿐 아니라 `packages/`도 포함한다(공유 패키지를 놓쳐 전체 사용자 회귀가 났다).
- 민감 컬럼은 API에서 필드를 가리는 것으로 끝내지 않는다. anon/authenticated의 컬럼 select 권한을 회수하고, 마스킹 RPC나 뷰로만 노출한다. anon 키는 번들에 공개되어 있다.
- 기밀 구성값(배분율·요율 구조 등)은 서버에서 계산한 최종값만 반환한다. 다른 사람·조직을 조회할 수 있는 파라미터를 두지 않고, 인증된 본인 기준으로 서버가 해석한다.
- 권한 체크는 `role === 'admin'` 직접 비교 대신 앱별 관리자를 함께 인정하는 헬퍼(`canManageApp(appId)` / 서버 `requireAppAdmin(appId)`)로 한다. 클라이언트·서버·메뉴 선언(`adminOnly` 플래그) 세 곳 모두에서 같은 버그가 났다.
- 같은 쓰기 작업은 SECURITY DEFINER RPC 하나로 모으고 권한 검사를 RPC 안에서 한다. 앱마다 쓰기 코드를 두면 게이트가 갈라진다.
- 유한한 값 집합을 갖는 text 컬럼에는 CHECK 제약을 건다. 삭제 가능한 레코드를 다른 곳에서 참조하면 AFTER DELETE 정리 트리거를 같이 설계한다. 둘 다 "에러 없이 조용히 사라지는" 결함이다.
- 새 테이블 GRANT: Supabase는 2026-10-30부터 public 신규 테이블에 Data API 권한을 자동 부여하지 않는다. `ALTER DEFAULT PRIVILEGES`로 기본 권한을 마이그레이션에 명시한다.

### 클라이언트
- **조회 실패를 "없음"으로 취급하지 않는다.** supabase-js는 네트워크 실패에도 throw하지 않고 `{ data: null, error, status: 0 }`을 반환한다. status는 `error.status`가 아니라 응답에 있다. 오프라인 상태의 `getSession()`은 `session: null`을 준다. 화면 분기나 "없으면 생성" 판단 전에 transient(0/408/5xx)를 걸러 "연결 오류 + 다시 시도" 상태로 보낸다. 승인된 사용자가 네트워크가 끊기자 승인대기 화면으로 갔고, 중복 등록 요청도 발생했다.
- 같은 프로젝트로 `createClient`를 두 번 이상 만들면 `storageKey`를 분리한다. `detectSessionInUrl: true`는 콜백을 받는 라우트에서만 켠다. 다른 클라이언트가 OAuth 해시를 가로채 원인 모를 401이 났다.
- 스토어 로더는 in-flight 공유 + TTL 표준 헬퍼 하나로만 만든다. 직접 짠 1분 TTL이 egress 3.5GB 급증을 일으켰다. 최소 2분, 기본 5분으로 하고 `select('*')`는 금지한다.
- **낙관적 반영 + fire-and-forget 저장 금지.** 저장 성공을 확인한 뒤 상태를 반영한다. 기기마다 상태가 달라졌다.
- **로컬 캐시 기준으로 행 전체를 upsert하면** 로그인 직후 stale 캐시 때문에 다른 필드가 통째로 지워진다. 쓰기 전에 인증된 최신값을 강제로 재조회하거나 부분 patch로 쓴다.
- 낙관적 잠금에서 `expectedUpdatedAt` 조회가 실패해 null이 되면 "잠금 없이 저장"으로 빠지면 안 된다. 재시도하고, 그래도 없으면 저장을 막는다. 3-way 병합 결과는 재시도 한도를 넘어도 버리지 말고 로컬에 유지한다.
- 파생 스냅샷(티켓·캐시 테이블)은 원본이 바뀌는 모든 경로에서 동기화한다. 발급 시점에만 갱신했더니 재배정이 현장 스캐너에 반영되지 않았다.

## 3. 프론트엔드 성능·번들

- 엔트리 청크가 크면 청크→모듈 매핑부터 덤프한다(임시 vite config 플러그인으로 `renderedLength`를 TSV로 출력). 초기 로드 405→195KB gzip은 import 2줄 수정 + 청크 분해로 얻었고, 처음 의심했던 스토어 분리는 하지 않는 것으로 결론 났다.
- 항상 마운트되는 컴포넌트(Layout/TopBar/Sidebar/CommandPalette/알림벨)에서는 배럴(`index.ts`) import를 금지한다. 배럴 하나가 리치텍스트 에디터 1MB를 엔트리로 끌고 왔다.
- `manualChunks`에 초기 필수 의존성(zustand)과 특정 화면 전용 무거운 의존성(html2canvas)을 같이 넣지 않는다. 하나라도 초기 그래프에 있으면 청크 전체가 로드된다.
- firebase, qrcode, html2canvas 등은 동적 import로 쓴다.
- 수천 행 리스트는 가상화하되, 임계값(예: 60행) 이하에서는 꺼서 기존 동작을 유지한다.
- 대형 파일 분해는 순수 헬퍼 추출부터 한다(동작 변경 없음). god component의 JSX 분해는 동시 편집 중인 영역을 피해서 한다.

## 4. React 패턴

- 제출·삭제 핸들러의 재진입 가드는 `useRef`로 한다. `if (busy) return; setBusy(true)`는 다음 렌더에야 반영되므로 모바일 인앱브라우저의 더블탭에 뚫려 데이터가 중복 생성된다. state는 UI 비활성 표시에만 쓴다.
- 네이티브 `alert`/`confirm` 대신 toast·confirmDialog 헬퍼를 둔다. 발행 헬퍼가 없으면 alert가 남발된다(68곳을 정리했다).
- 같은 타입을 import해 놓고 useState 초기값에 필드를 손으로 다시 나열하지 않는다. 필드 추가 시 그쪽만 누락된다.
- `select ... as Type`은 select 문자열이 리터럴이 아니면 추론이 실패해 빌드가 깨진다. `as unknown as Type`을 쓰거나 리터럴로 쓴다.
- UI 설정이 실제 동작에 배선되어 있는지 확인한다. 관리 화면에 셀렉트는 있는데 읽는 코드가 없는 "죽은 설정"이 있었다. 배선된 대상 레지스트리를 두고 나머지는 disabled로 표시한다.
- 아이콘 화이트리스트(DynamicIcon 등)를 쓰면 새 메뉴 등록 시 import와 MAP 양쪽에 추가한다. 빠뜨려도 에러 없이 아이콘만 사라진다.

## 5. CSS / Tailwind / 반응형

- **존재하지 않는 CSS 변수를 지어내지 않는다.** Tailwind v4의 `bg-(--x)`는 토큰이 없어도 빌드·lint를 통과하고 런타임에 조용히 무효가 된다. 쓰기 전에 `grep -o -- "--prefix-[a-z0-9-]*" src/index.css | sort -u`로 실재 여부를 확인한다.
- Tailwind 클래스를 문자열 보간으로 만들지 않는다(`md:${x}`는 생성되지 않는다). 주석에 클래스명을 적어도 CSS가 생성된다.
- 바텀시트↔사이드패널 전환은 `lg:` 기준으로 하고, 트리거·시트·패널 세 곳의 브레이크포인트를 일치시킨다. 태블릿 세로(768~1023px)에서 버튼을 눌러도 아무것도 뜨지 않는 사각지대가 생겼다. 상세 쪽이 캔버스·표처럼 가로 공간을 많이 먹으면 `md:`에서 짜부라진다.
- 한글 UI에는 `word-break: keep-all`을 건다(기본값은 단어 중간에서 줄바꿈된다). "라벨 + 큰 숫자"는 좌우 배치 대신 세로 스택으로 한다. 좌우 배치가 필요하면 라벨에 `min-w-0 flex-1`, 값에 `shrink-0 whitespace-nowrap`을 준다.
- html2canvas는 `text-overflow: ellipsis`(truncate) 텍스트를 엉뚱한 글자로 그린다. 캡처 대상에서는 truncate를 제거한다.
- iOS Safari의 `input[type=date|month|time]`은 height를 무시한다. `appearance: none` + `::-webkit-date-and-time-value { text-align:left; margin:0 }` + `::-webkit-datetime-edit { padding:0 }`을 전역에 둔다. select에는 appearance를 건드리지 않는다.
- 다크모드·색상 이관 전에 `grep -c "dark:" file`로 화면별 기존 전략을 확인한다. `dark:`를 이미 쓰는 화면은 빠진 곳만 보완하고, 0개인 화면만 토큰으로 전면 교체한다.
- 고정 폭 캔버스 안의 fixed FAB·토스트는 뷰포트 우측이 아니라 `left-1/2 -translate-x-1/2`로 배치하고, 하단 탭바 높이 + safe-area만큼 띄운다.

## 6. UI·디자인 원칙

- 부트스트랩·머티리얼 패턴(단색 채움 카드, 왼쪽 컬러 바, 진한 필박스 배지, 제목마다 붙는 원형 아이콘 배지)을 피한다. 그림자 색조, 미세한 톤 차이, 타이포 위계로 구분한다(Linear/Stripe/Notion/토스 수준).
- UI에 이모지를 쓰지 않고 lucide-react 아이콘을 쓴다. 장식용 아이콘 배지도 쓰지 않는다.
- 아이콘만 있는 버튼은 금지한다. 짧은 텍스트 라벨을 항상 함께 둔다(사용자 연령대가 높으면 더욱).
- 액션 버튼 2~3개를 `flex-1`로 늘리지 않는다. 내용 크기로 두고 마지막 액션은 `ml-auto`로 붙인다.
- 색·투명도 재조정은 이전 조정폭의 2배 이상으로 한다(4~6%p 차이는 체감되지 않는다). 그래도 "칙칙하다"는 반응이 나오면 채움을 없애고 보더에만 색을 남긴다.
- "Figma 같은 컴팩트함"은 크기를 줄이는 것이 아니라 네이티브 폼 크롬(range, color input)을 제거하는 것이었다.
- 입력이 있는 모달·바텀시트는 배경 클릭으로 닫지 않는다. 드래그 선택이 배경에서 끝나도 닫혀서 입력이 날아간다. 명시적 X·취소 버튼으로만 닫는다.
- 관리자가 시각물을 만드는 화면에는 폼과 함께 실시간 미리보기를 둔다.
- 템플릿 갤러리와 사용자 콘텐츠를 같은 카드로 섞지 않는다. 기본 화면은 "내가 만든 것"으로 하고, 템플릿은 "새로 만들기" 진입점으로 분리한다.
- 같은 메뉴가 여러 앱에 있으면 "여기는 관리, 저기는 조회"를 화면에 명시한다. 우연히 한쪽에만 수정 버튼이 있는 상태를 만들지 않는다.
- 사용자 행동을 유도하는 화면에는 넛지(좋은 기본값, 주 CTA 1개, 마감 강조, 완료 피드백)를 화면당 1~2개 넣는다. 거절·불참 경로를 어렵게 만드는 다크 넛지는 금지한다.

## 7. 보고서·문서

- 경영진용 보고서는 데이터 기반으로 담백하게 쓴다. "이것이 ~의 실체다" 같은 결론짓기, 수사적 질문, 컬러 "발견!" 콜아웃을 쓰지 않는다.
- 경영진 보고서에는 개발 위생 이슈(잔여 디렉토리, 네이밍 실수)를 넣지 않는다. 채팅에서 한 줄로만 언급한다.
