시드 만들기

투자금이 없어 시작하지 못하는 사람이 큰 돈의 흐름을 간단히 기록하고, 매달 현실적인 시드를 만들어가는 가이드.

지출을 완벽하게 분류하는 가계부가 아니다. 계획한 돈, 실제로 확보한 돈, 투자 계좌에 넣었다고 기록한 돈을 구분한다.

대상: 시드 0원부터 시작하는 개인·가구상태: 구현 전 의사결정용원칙: 기존 가상자금 흐름 변경 없음
결정이용 흐름화면 예시입력 설계분석 규칙시드별 선택지기존 기능 경계현행 구현 점검UI/UX 개선기획 고도화구축 단계
01 / WHY

핵심 결정

문제

가상자금은 자유롭게 설정할 수 있지만 실제 투자 가능한 돈을 증명하지는 않는다. 수입과 큰 지출을 보지 못하면 월 투자액이나 지속 가능한 루틴을 정하기 어렵다.

제품 원칙

입력 자체가 목적이 아니다. 월별 큰 항목을 입력하면 변화가 보이고, 사용자가 그중 무리 없이 확보할 금액을 결정하도록 돕는다.

기본 경로는 그대로: 이 가이드를 쓰지 않는 사람은 지금처럼 가상 시드를 설정하고 기존 투자 기능을 사용한다. 가이드 기록은 명시적 선택 없이는 가상 계좌, 자동 입금, 자동매매 설정에 영향을 주지 않는다.

02 / JOURNEY

기록에서 투자 기반까지

수입·큰 지출 입력→전월·최근 추이 확인→이번 달 시드 계획→실제 확보 기록→입금 기록
처음

0원에서도 시작

가구 유형과 이번 달 수입·지출을 대략 입력하거나, 바로 소액 목표를 정한다. 세부 거래나 카드 등록은 필수가 아니다.

매월

변화에 맞게 조정

지난달 값을 참고로 보며, 사용자가 “지난달 값 채우기”를 눌렀을 때만 반복 항목(급여·주거·통신 등)을 채운다. 일시 항목은 절대 복사하지 않는다. 차량 수리비 같은 일시 지출이 있으면 시드 목표를 낮추거나 0원으로 둘 수 있다.

1년

실제로 만든 돈 확인

월별 확보금과 누적 원금을 본다. 미실현 수익이나 가상의 복리 금액을 확보한 시드에 합산하지 않는다.

03 / UX

첫 화면 제안

다음은 설명용 예시이며 실제 사용자 데이터나 성과 전망이 아니다.

시드 만들기 · 9월사용자 기록 기준
이번 달 계획5만 원
실제 확보3만 원
입금 기록0원
월별 확보금 / 실제 기록과 다음 달 계획 구분
6월7월8월9월10월 계획

올해 실제 확보 10만 원. 이달에는 계획까지 2만 원 남았습니다. 계획은 언제든 조정할 수 있습니다.

모바일에서도 숫자와 그래프를 먼저 보여주고, 입력은 월 요약 행을 눌러 편집한다. 색만으로 계획과 실제를 구별하지 않고 텍스트·선 형태도 함께 쓴다.

04 / INPUT

단순 입력, 선택적 세분화

영역처음 보이는 입력원할 때만 더 입력
가구혼자 / 외벌이 / 맞벌이 선택본인·배우자 수입 분리, 가구원 표시명
수입가구 월수입 합계사람별 급여일, 인센티브·휴가비·연말정산 환급 등 발생 월의 추가 수입
지출식비·생활, 주거, 차량, 교육, 세금·보험, 통신·구독, 기타미분류 카드대금, 2개월 단위 수도·가스요금, 주민세·재산세·자동차세, 연말정산 추가 납부
카드카드 등록 없이 미분류 결제대금만 선택 입력카드 별칭·명의·결제일, 카드별 월 대금 및 상세 내역(후속)
시드월 계획금, 실제 확보금날짜별 여러 번 확보, 사용·취소, 증권계좌 입금 기록

급여일이 다른 가구: 월수입은 합산해 월간 여력을 살펴보되, 본인 25일·배우자 5일처럼 유입 날짜를 따로 표시한다. 월 전체 여력을 월초의 현금으로 취급하지 않는다. 지출 결제일과 실제 계좌 잔액을 모르면 날짜별 투자 가능액은 추정하지 않는다.

월별 직접 입력: 지난달 수입·카드대금·고정비를 새 달로 자동 복사하거나 다음 달 투자 여력을 확정하지 않는다. 두 달치 공과금과 일시 수입·세금은 발생 월에 전액 기록한다. 새 달 금액을 입력하면 지난달 대비 투자 여력의 + / - 차이를 참고로 보여준다.

중복 계산 방지: 카드대금 총액만 입력했다면 지출로 계산한다. 같은 카드의 사용 내역을 항목별로 기록했다면 카드대금 출금은 결제 확인으로만 처리한다. 두 입력 방식을 섞을 때는 해당 카드·해당 월의 포함 범위를 명시해 겹치는 금액을 제외한다. 명의자와 실제 사용자는 서로 다른 선택 속성이다.

05 / INSIGHT

분석은 비난 대신 선택지를 준다

지출의 변화

전월 대비 카테고리별 증감과 투자 여력의 + / - 차이를 먼저 보여준다. 세금·차량 수리·격월 공과금 등 한 번의 급증을 반복 누수로 판정하지 않는다. 확보하지 못한 여력을 모두 써버린 돈으로 표현하지 않는다.

시드 제안

예: “최근 구독비가 매달 2만 원 늘었습니다. 다음 달부터 월 1만 원을 조정해 실제로 확보하면 1년간 추가 원금은 12만 원입니다.” 제안 수락은 계획만 바꾸며, 확보 완료로 자동 처리하지 않는다.

금융 안전선

투자 여력은 수입에서 지출과 사용자가 정한 생활·비상자금 여유를 뺀 참고값이다. 0원 이하이면 절약이나 투자 압박 대신 이번 달 목표를 쉬도록 제안한다. 계획액은 사용자가 결정한다.

투자 후 여유

실제 입금 원금, 평가손익, 실현손익, 인출 가능한 금액을 구분한다. 수익률 시나리오는 손실 가능성과 세금·수수료 영향을 알리고 가정으로만 표시한다. 예·적금보다 높은 수익을 보장하지 않는다.

계산 예시: 월 3만 원을 실제로 더 확보하면 12개월 추가 원금은 36만 원이다. 이는 미래 투자 수익도, 이미 생긴 돈도 아니다. “줄일 수 있음”과 “줄여서 확보함”을 분리해 보여준다.

06 / NEXT STEP

시드 규모에 맞는 다음 행동

돈을 모은 다음에도 살 수 있는 것과 사도 되는 것은 다르다. 시드 형성 가이드의 결과는 매수 명령이 아니라 현재 자금으로 가능한 선택지를 설명하는 안내다.

상황보여줄 선택지피해야 할 유도
아직 입금 기록이 없거나 가용 현금이 없음시드 확보 루틴 유지, 목표 조정계획금이나 확보금만으로 매수 가능한 것처럼 표시
검토 중인 종목 1주 가격과 예상 비용이 가용 현금보다 큼목표 금액까지 대기, 자금에 맞는 ETF 등 별도 적합성 검토가격만 낮은 종목을 대체품으로 추천
1주 매수는 가능하지만 적합한 후보가 없음현금 대기, 다음 적립일까지 기다리기남은 돈을 쓰기 위해 임의 종목 매수
가격·투자 근거·위험 한도가 모두 맞음1주 단위 계획, 매수 후 남는 현금과 비용 표시수익 보장 또는 빈번한 매매로 시드가 빨리 늘 것이라는 암시

예시: 가용 현금이 10만 원이고 관심 종목 1주가 13만 원이면 매수 가능 수량은 0주다. 모자란 금액을 보여주되, 기다리기와 별도 기준을 통과한 대안 탐색을 함께 제시한다. 저가 종목이나 ETF도 가격만으로 통과시키지 않는다.

자금 계산의 기준

사용자 입금 기록은 잔고 검증이 아니므로, 실제 가용 현금은 사용자가 확인하거나 계좌 연동 후 확인해야 한다. 1주 가능 여부는 최신 가격, 매수 예상 비용, 사용자가 남겨둘 현금, 이미 보유한 자산을 반영해 보수적으로 판단한다. 가격이 없거나 오래됐으면 가능 여부를 확정하지 않는다.

ETF와 단기매매

ETF는 분산 접근의 후보일 뿐 원금 보장 수단이 아니며 가격·유동성·추종 대상·총보수·계좌에 적용되는 세금 및 거래비용을 비교한다. 소액 시드를 빠르게 키우기 위한 잦은 매매는 손실·수수료·스프레드·세금 부담이 커질 수 있어 기본 추천 전략으로 삼지 않는다.

추천 경계: 기존 앱의 후보 적합성 판단을 가격 필터로 대체하지 않는다. 이 문서의 ‘추천’은 구매·대기·추가 적립 중의 선택지 안내를 뜻한다. 실제 종목·ETF 추천 규칙, 개인별 위험 성향, 상품 적합성 및 세제는 별도 검증 후 연결한다.

07 / CONTRACT

기존 기능과 신뢰 경계

상태뜻앱에서 허용하는 동작
계획금앞으로 모으기로 한 금액목표 추이에만 사용, 투자 가능 잔액에 포함하지 않음
확보금투자용으로 실제 따로 둔 돈이라는 사용자 기록시드 형성 누계에 반영, 계좌 잔고로 취급하지 않음
입금 기록증권계좌에 넣었다는 사용자 기록명시적 확인 후 시뮬레이터의 계획 입력값으로 제안 가능
가상자금기존 앱의 자유 설정값새 가이드 사용 여부와 무관하게 기존대로 유지
  • 확보한 돈을 계좌로 옮길 때는 자금의 상태를 변경한다. 같은 돈을 확보금과 계좌 입금액에 더해 총시드를 이중 집계하지 않는다.
  • 수동 입력은 검증된 은행·증권사 잔고가 아니다. 계좌 연동은 별도 보안·동의 검토가 필요한 후속 과제다.
  • 사용자·가구별 접근 통제, 가구원별 열람 권한과 탈퇴 시 삭제 정책을 설계한다. 카드번호 등 결제정보 원문은 MVP에서 받지 않는다.
  • 가이드를 끄거나 기록을 삭제해도 기존 가상 계좌, 월 자동 입금, 투자·매매 데이터는 변경하지 않는다.
09 / REVIEW

기획안과 현행 구현의 차이

현재 화면(features/seed-builder)을 이 문서와 대조한 결과다. 문서가 약속했지만 화면에 없는 것, 화면이 문서와 어긋나는 것을 구분했다.

구현 현황 (2026.09.30): UX-1(건너뜀·0원·기록 없음 구분), UX-4(저장 안 됨·인라인 이동 확인), UX-5(확보 내역·취소·되돌리기), UX-6(적자·쉬기), UX-7 일부(계획 눈금·다음 달 점선 막대), 입금 기록(확보 내역의 부분합), 다음 달 계획 입력, 지난달 값 채우기를 반영했다. 남은 것: 온보딩(UX-2), 금액 입력 보조(UX-3), 변동 상위 항목(UX-8), 다음 행동 진입(UX-9), 접근성(UX-10), 목표 설정 방식·안전 완충 개월 수·금액 가리기·전체 삭제.

구분문서의 약속현행 화면조치
누락계획·확보·입금 기록 3단계 상태계획·확보 두 값만 있음. 입금 기록 필드·표시 없음입금 기록 추가(아래 P1). 확보와 입금의 이중 집계 방지 규칙 필요
누락한 달 여러 번 확보, 사용·취소, 일부 입금월당 단일 숫자 saved. 수정하면 이전 값이 사라짐확보 “내역(이벤트)” 모델로 전환. 월 합계는 내역의 합
누락계획(점선)과 실제(실선) 구분 그래프, 다음 달 계획 표시확보금 막대만 표시. 계획선 없음. 다음 달 이동 자체가 막혀 있어 미래 계획 입력 불가계획 마커·달성률 표시, 다음 달 “계획만” 입력 허용
모순이용 흐름은 “전월 값 불러오기”, 입력 설계는 “자동 복사 안 함”불러오기 없음. 매월 빈 화면에서 전부 재입력“지난달 값 채우기” 버튼으로 통일(반복 항목만, 사용자 클릭 시). 위 본문 수정 완료
불일치여력 0원 이하이면 “이번 달은 쉬기”를 제안여력을 Math.max(0, …)로 잘라 적자 규모가 사라짐. 쉬기 제안 없음적자를 그대로 표시하고 쉬기 안내 문구 추가
불일치월 요약 상단에 입력 결과 반영상단 카드는 저장된 값만 반영. 입력 중인 초안과 숫자가 어긋남상단 카드에 “저장됨/입력 중” 구분 또는 초안 미리보기
불일치“첫 화면은 숫자와 그래프, 입력은 월 요약 행을 눌러 편집”한 페이지에 폼 전체(수입·지출·비정기·계획·비교·다음 행동)가 세로로 나열단계형 입력 + 접이식 섹션(아래 UX-2)

UI/UX 개선안

우선순위: P0 신뢰·정확성 결함, P1 핵심 흐름 완성, P2 편의·완성도.

#문제개선순위
UX-10원 미입력과 “입력하지 않음”이 구분되지 않는다. 건너뛴 달과 0원 달이 같은 모습이다.월 상태를 기록 없음 / 건너뜀 / 기록됨으로 분리. 그래프에서 건너뜀은 빈 점선 칸, 0원 확보는 “0” 라벨이 붙은 얇은 막대로 표시.P0
UX-2시작 화면부터 입력칸이 20개 이상 보여 “간단히 시작”이라는 약속과 어긋난다.첫 방문은 3단계 온보딩: ① 가구 형태·월수입 ② 이번 달 큰 지출 한 줄(“대략 얼마나 나가나요?”) ③ 이번 달 목표. 세부 항목(세금·카드·비정기·추가 수입)은 “더 자세히”로 접는다. 각 단계는 건너뛸 수 있고 결과 카드가 즉시 갱신된다.P1
UX-3금액 입력이 type=number 원 단위라 자릿수를 세기 어렵고, 오타(0 하나 추가)를 알아채기 어렵다.천 단위 쉼표 자동 표시, 입력칸 아래 “약 350만 원” 한글 보조 표기, +1만 / +5만 / +10만 빠른 증감 버튼. 모바일에서는 숫자 키패드(inputmode="numeric").P1
UX-4“이번 달 저장” 한 버튼만 있고 저장 여부를 알기 어렵다. 월 이동 시 브라우저 confirm 창이 뜨고, 연도가 바뀌면 입력 중인 값이 조용히 사라진다.수정 즉시 “저장 안 됨” 배지 + 하단 고정 저장 바(모바일). 월 이동은 인라인 배너(“저장하고 이동 / 버리고 이동”)로 교체. 연도 경계에서도 같은 보호 적용.P0
UX-5확보금이 단일 숫자라 “언제 얼마를 모았는지”가 남지 않고, 수정하면 이력이 덮어써진다.“+ 확보 기록” 버튼(날짜·금액·메모 선택). 월 카드에 내역 목록, 각 내역은 취소(삭제 아닌 취소선+되돌리기). 합계는 자동 계산.P1
UX-6여력이 음수여도 0원으로 표시되고, 목표가 여력을 넘으면 경고 한 줄만 나온다.여력 카드를 세 상태로 표시: 여유(+), 빠듯함(목표≥여력의 80%), 적자(−, 금액 그대로). 적자일 때는 경고 대신 “이번 달은 쉬어도 좋아요 · 목표 0원으로 설정” 단일 버튼 제안. 색만이 아니라 아이콘·텍스트도 함께.P0
UX-7차트가 12개월 막대뿐이라 “계획 대비 얼마나 했는지”와 “올해 총합”의 맥락이 약하다.막대에 계획 눈금(가로선) 겹치기, 선택 월 툴팁(계획·확보·입금), 상단에 “올해 누적 확보 / 올해 계획 합계” 진행바. 미래 달은 점선 막대(문서 화면 예시와 일치).P1
UX-8“지출 변화 보기”가 전 항목을 나열해 어디가 중요한지 보이지 않는다. 구독 제안만 하드코딩되어 있다.변동폭 상위 3개만 기본 표시(“전체 보기” 접기). 일시성 항목(세금·격월 공과금·수리비)은 “일시” 라벨을 붙여 증가 경고 대상에서 제외. 제안 문구는 항목별 템플릿으로 일반화.P2
UX-9“시드에 맞는 다음 행동”이 기록 화면 맨 아래에 붙어 있어 도달하기 어렵고, 시뮬레이터 이동은 값 하나만 전달한다.월 카드에 “이번 달 확보 완료 → 다음 행동 보기” 진입 버튼. 결과 문구는 4가지 상태(대기/모자람/1주 가능/근거 필요) 카드로 정리. 시뮬레이터 이동 전 “전달되는 값 / 바뀌지 않는 것” 확인 시트를 보여준다.P2
UX-10접근성: 막대 그래프 대체 텍스트가 길고, 라벨이 label 안에 단위와 뒤섞여 있다. 오류는 하단 상태줄에만 나온다.차트 아래 “표로 보기” 토글, 입력칸별 인라인 오류와 aria-describedby, 포커스 이동(저장 실패 시 첫 오류 칸). 최소 터치 영역 44px.P2

11 / PRODUCT

기획 고도화

1. 목표 설정 방식 세 가지

월 목표를 매번 직접 정하기 어렵다. 사용자가 기본 방식을 고르게 한다: 고정 금액(매달 5만 원), 여력 비율(참고 여력의 30%), 연 목표 역산(올해 100만 원 → 남은 달 균등). 모두 “제안값”이며 최종 금액은 사용자가 수정한다. 못 모은 달의 부족분은 다음 달 목표에 자동으로 얹지 않는다.

2. 안전 완충 단계(비상자금 우선)

“남겨둘 돈”을 빈칸으로 두지 않고 생활비 대비 개월 수로 안내한다. 예: 월 지출의 1개월치를 먼저 두고 시드 확보를 시작할지, 병행할지 사용자가 선택. 미달 상태에서도 확보를 막지 않되, 진행 상황을 “안전 완충 0.6개월” 같은 숫자로 보여준다. 투자를 재촉하거나 금지하지 않는다.

3. 소득 변동 대응

프리랜서·성과급 비중이 큰 가구는 월수입이 들쭉날쭉하다. “최근 3개월 중 가장 낮은 달” 기준의 보수적 여력을 보조 지표로 제공하고, 일시 수입은 목표 산정에서 기본 제외한다(사용자가 포함 선택 가능).

4. 비난 없는 지속 장치

연속 달성 기록(스트릭)은 실패 시 죄책감을 만든다. 대신 “올해 실제 확보한 달 수 / 기록한 달 수”와 쉬어간 달도 정상 기록임을 표시한다. 3개월 이상 기록이 없으면 알림 대신 다음 방문 시 “다시 시작하기(지난 기록 유지)” 안내만 한다.

5. 앱 전략과의 정렬

이 앱은 종목 선별 우위를 주장하지 않고 정기 지수 매수·행동 편향 차단·리스크 관리를 가치로 삼는다. 따라서 6장의 “1주 가격 비교”를 중심에 두지 않고, “확보한 돈 → 정기 적립액 → 적립 주기” 흐름을 기본 선택지로 앞세운다. 예: “월 5만 원이면 ○○ ETF 1주(13만 원)를 3개월에 한 번 살 수 있어요”. 종목 추천이 아니라 적립 주기 계산이며, 수익을 암시하지 않는다.

6. 시뮬레이터와의 연결 계약

현재는 이동 시 금액 한 값만 전달한다. 3단계에서는 전달 항목(확인한 가용 현금, 월 적립 후보액)과 전달하지 않는 항목(수입·지출 원본, 확보 내역)을 화면에 명시하고, 전달은 항상 사용자의 명시적 클릭으로만 일어난다. 시뮬레이터에서 “시드 만들기로 돌아가기”를 제공해 흐름이 끊기지 않게 한다.

7. 개인정보·민감도

수입·지출은 민감 정보다. 기존 UI_STRICT_IDENTITY 정책을 이 API에도 동일 적용하는지 검수 항목에 넣고, 화면에 “내 기록만 볼 수 있음 · 전체 삭제/내려받기” 위치를 상시 노출한다. 스크린샷 공유 시를 위해 금액 가리기 토글을 제공한다.

8. 성공 지표(출시 후 점검)

가상 데이터 없이 기능 자체의 건강도만 본다: 첫 방문 후 첫 저장 도달률, 첫 달 이후 다음 달 재방문율, 월 계획 대비 확보 비율의 중앙값, 입력 이탈이 많은 단계. 투자 수익·매수 전환은 지표로 삼지 않아 매수 유도를 방지한다.

데이터 모델 변경 메모: ① 월 기록 상태(none/skipped/recorded) ② 확보 내역 테이블(날짜·금액·취소 여부) ③ 입금 기록 필드(확보 내역에서 “계좌 입금”으로 표시된 부분합) ④ 목표 방식(고정/비율/연 목표). 기존 saved 합계는 마이그레이션 시 “확보 내역 1건”으로 옮겨 값이 바뀌지 않게 한다. 현행 마이그레이션 019~021과 호환되도록 추가 마이그레이션으로만 변경한다.

12 / DELIVERY

구축 순서와 검수

MVP / 시드 형성

작게 시작

별도 메뉴, 선택형 시작, 가구 총수입·큰 지출, 월 시드 계획·확보·입금 기록, 월별 그래프. 0원·지출 미입력·중간 건너뛴 달에도 사용 가능. UX-1·4·6(P0)을 먼저 반영한다.

2단계 / 분석

변화 이해

3단계 온보딩(UX-2), 확보 내역(UX-5), 계획 대비 그래프(UX-7), 지난달 값 채우기, 최근 3개월 비교, 큰 항목 변화 설명, 목표 설정 방식 세 가지, 안전 완충 개월 수 표시.

3단계 / 연결

투자 계획으로

사용자가 확인한 가용 현금으로 적립 주기·대기·ETF 등 선택지를 안내한다(11장 5·6항). 명시적 확인 뒤 시뮬레이터 계획값으로만 전달한다. 자동매매·가상 시드 자동 동기화는 하지 않는다.

출시 수용 기준

  • 시드 0원 사용자가 세부 거래 없이 첫 월 계획을 만들고, 다음 달에는 전월 값을 불러와 변경 항목만 고칠 수 있다.
  • 외벌이·맞벌이에서 가구 합계가 사람별 합과 일치하고, 카드 명의와 사용자가 다른 경우에도 카드대금이 이중 집계되지 않는다.
  • 기록 수정·취소, 한 달 여러 번 확보, 일부 계좌 입금, 일시 지출 급증, 0원 월에도 실제 누계와 계획선이 구분된다.
  • 10만 원으로 13만 원짜리 종목을 1주도 살 수 없다고 표시하고, 가격이나 시세가 불확실하면 매수 가능하다고 단정하지 않는다. 적합한 대안이 없으면 대기가 정상적인 결과다.
  • 가이드 미사용·중단·삭제 후에도 기존 가상 시드와 자동 입금/매매 설정이 동일하다. 이 기준이 깨지면 연동 출시를 보류한다.
  • 여력이 마이너스인 달에 적자 금액이 그대로 보이고, “쉬어도 좋아요” 제안이 나온다. 0원으로 잘려 표시되지 않는다.
  • 저장하지 않은 입력이 있을 때 월·연도 이동, 새로고침, 탭 이동 어디서도 값이 조용히 사라지지 않는다.
  • 건너뜀·0원 확보·기록 없음 세 상태가 그래프와 표에서 서로 다르게 보이고 스크린리더로도 구분된다.
  • 기존 saved 값이 확보 내역 모델로 이전된 뒤에도 월·연 합계가 이전과 정확히 같다.

남은 결정

가구 공동 기록을 공유할지, 단일 사용자에게 가구원 별칭만 제공할지 결정해야 한다. MVP는 단일 사용자 소유 + 가구원 별칭으로 시작하고, 공동 편집과 계좌 연동은 별도 권한·개인정보 검토 후 진행하는 편이 안전하다.

  • 확보와 입금의 관계(결정·구현됨): 입금 기록은 확보 내역의 부분합이다(“확보 3만 원 중 2만 원 입금”). 입금은 확보 금액을 넘을 수 없다.
  • 미래 달 입력(결정·구현됨): 다음 달까지 계획만 허용하고, 확보·입금은 서버에서도 거부한다.
  • 목표 기본값: 신규 사용자에게 어떤 방식을 기본으로 켤지(고정 금액 권장, 값은 비워 둠).
